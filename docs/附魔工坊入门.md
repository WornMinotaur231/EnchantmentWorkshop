# Enchantment Workshop / 附魔工坊 1.0.0 · 附魔工坊

Paper 26.3 / Java 25。安装 `EnchantmentWorkshop-1.0.0.jar` 后即可在游戏里制作附魔，无需客户端模组。

## 从模板创建

OP 输入 **`/ew editor`**。

1. 点击底部绿宝石「从模板新建」。
2. 选择「吸血之剑」「冰霜之剑」「夜视头盔」等模板。
3. 在聊天栏输入唯一英文 ID，例如 `venom_blade`。此条输入由编辑器拦截，不公开发送。
4. 点击「显示名称」，输入中文名称；点击其他按钮修改等级、描述和获取途径。
5. 点击「适用物品标签」，选择剑、镐、头盔等装备，同时设置对应槽位。
6. 点击「效果 1」调整参数；点击「添加一个效果」组合更多效果。
7. 点击绿色「校验并保存」进入预览，核对后点击「确认保存」。确认前关闭页面或返回列表，草稿不会写入文件。

**新 ID 首次注册需要完整重启服务端。** 页面和消息会区分已保存与已生效。重启后可用 `/ew give 你的名字 venom_blade 1` 获取原生附魔书。

已有附魔的效果数值、概率、药水参数和说明可以即时修改。若配置里另有待注册的新附魔或注册属性变动，整份配置会等待重启，避免显示信息与实际效果不一致。

输入窗口有效期 2 分钟。聊天输入 `取消` 返回草稿；`/ew cancel` 取消输入；`/ew editor` 重新打开工坊。校验失败可以继续修改，只有保存成功才写入文件。

## 从空白创建

在工坊首页点击「从空白创建」，依次输入显示名称和代码名称，选择适用物品，再编辑可编程规则的触发行为、条件和动作。空白附魔默认不进入随机获取池；可在附魔编辑页开启附魔台、村民交易或战利品获取。

详细步骤见 [可编程附魔说明](可编程附魔说明.md)。

## 多选装备槽位与冲突附魔

在附魔编辑页点击「生效装备槽位」，通过灰色 / 绿色选项勾选多个槽位。支持主手、副手、头部、胸部、腿部、脚部，以及双手、全部护甲、任意槽位这些组合。各选项取并集，至少保留一个；「重置为主手」可恢复常见设置。槽位仍须与适用物品相符，例如胸甲应选择胸部槽位。

点击「冲突附魔」可分页多选服务器已注册的原版 / 其他插件附魔，以及当前草稿中的本插件附魔；不显示自身，尚未保存的新附魔也可作为候选。原版名称跟随客户端语言，本插件名称使用配置的显示名称。点击「无冲突 / 清空选择」可清空列表。

两个菜单均点击「完成选择并返回」回到草稿，再按「校验并保存」预览确认。勾选不会立即写文件；槽位和冲突关系属于注册信息，保存后完整重启生效。

规则页的「无条件」和条件列表中的「无条件」均会清空该规则原有条件，表示条件检查始终满足。触发行为、概率、冷却、生效槽位和世界禁用等规则仍有效。配置中对应 `conditions: {}`，无需新增条件键。

## 删除整个附魔

图形界面：`/ew editor` → 选择已有附魔 → 右下角「删除整个附魔」→ 查看名称、ID、冲突引用与生效说明 →「确认删除整个附魔」。取消会返回原草稿。删除只操作已保存定义，不会顺带保存其他草稿修改。

指令：先运行 `/ew delete lifesteal` 查看删除信息，再在两分钟内运行 `/ew delete lifesteal confirm` 或 `/ew delete lifesteal 确认`。需要 `enchantmentworkshop.admin` 权限，玩家与控制台均可使用。若预览后文件被其他管理员修改，确认会拒绝覆盖，请重新预览。

- 可删除本插件的内置附魔和自行添加的附魔；不删除原版或其他插件的附魔。
- 自动移除其他定义对该附魔的冲突引用，保留其他冲突关系。
- 允许删除最后一个附魔；文件保留 `enchantments: {}`，下次启动不会自动补回默认附魔，可以继续从空白或模板创建。
- 修改前备份为 `enchantments.yml.bak`；这是最近一次保存的备份，后续保存会覆盖它。
- 已注册的附魔要在**完整重启后**才能移除，删除保存后立即停止该附魔的运行效果；`/ew reload` 不能移除注册。
- 已有物品上的对应原生附魔可能在重启加载后丢失。删除前备份世界和玩家数据；只恢复配置备份不能保证找回物品上已经丢失的数据。若只是临时停用，可将「启用」改为关闭后重启，保留定义。
- `/ew remove <ID>` 仍然只移除主手物品上的附魔，与删除定义的 `delete` 不同。

规则编辑和预览中的触发行为、目标、动作、条件、天气、游戏模式、开关、槽位及常见药水显示中文；配置字段与资源 ID 保持原样，选择项保留代码提示。服务器全部物品类别、实体和自定义资源仍可使用原始 ID 识别，不改变现有配置格式。

## 用指令制作

需要 `enchantmentworkshop.admin` 权限，默认 OP 拥有。支持控制台和 Tab 补全。

```text
/ew create venom_blade frostbite 毒刃
/ew effect venom_blade set 1 potion minecraft:poison
/ew effect venom_blade set 1 duration-ticks 80
/ew effect venom_blade set 1 chance 0.30
/ew effect venom_blade add LIFESTEAL
/ew effect venom_blade set 2 value 0.10
/ew set venom_blade max-level 3
/ew set venom_blade description 有概率使目标中毒，并有概率吸血
/ew validate
/ew status
```

每条修改指令通过校验后立即保存文件。上例创建「毒刃」：从冰霜模板继承装备范围和获取方式，把第一个效果改为中毒，再增加吸血效果。首次创建完成后重启服务器。

```text
/ew copy venom_blade venom_blade_plus 强化毒刃
/ew effect venom_blade_plus remove 2
/ew set venom_blade_plus acquisition.villager-trade false
/ew set venom_blade_plus active-slots mainhand
/ew set venom_blade_plus conflicts enchantmentworkshop:lifesteal
/ew set venom_blade_plus conflicts []
/ew effect venom_blade_plus set 1 chance default
```

效果序号从 **1** 开始。`default` 恢复所选类型的默认字段值；不能删除最后一个效果。支持 8 类基础效果及 `PROGRAM` 可编程规则，一条附魔最多包含 16 个效果。规则内可设置触发行为、条件和动作；超出现有动作范围的行为需要扩展 Java 实现。

## 文件结构

```text
plugins/EnchantmentWorkshop/
  config.yml               通用设置：PVP、世界禁用、攻击蓄力
  enchantments.yml         所有附魔定义，包括内置与自行添加的附魔
  config-v1-backup.yml      首次拆分前的原配置备份
  enchantments.yml.bak      最近一次编辑器保存前的配置备份
```

编辑器和指令操作同一份 `enchantments.yml`，也可用文本编辑器修改；仅效果变更后执行 `/ew reload`，注册信息变更后完整重启。通用设置单独编辑 `config.yml`。

多个管理员同时编辑时，保存会检查文件是否已被其他人或外部编辑器修改。如有冲突，要求重新打开，避免覆盖他人修改。无效配置不会覆盖现有文件。

## 数值速查

| 字段 | 含义 | 示例 |
|---|---|---|
| `value` | 基础效果数值，比例使用小数 | `0.10` = 10% |
| `per-level` | 每升一级增加的数值 | `0.05` = 每级加 5 个百分点 |
| `chance` | 攻击效果触发概率 | `0.30` = 30% |
| `chance-per-level` | 每级增加的概率 | `0.10` = 每级加 10 个百分点 |
| `cooldown-ticks` | 攻击效果冷却 | `40` = 2 秒 |
| `potion` | 药水 ID | `minecraft:poison`、`minecraft:speed` |
| `duration-ticks` | 药水持续时间 | `80` = 4 秒 |
| `amplifier` | 药水强度从 0 开始 | `0` = I 级，`1` = II 级 |

药水名称和物品标签须为服务端已有的 ID，保存时会检查。基础攻击效果仅在主手近战触发；装备增益按槽位生效。`PROGRAM` 的触发范围由所选行为决定。选择模板可以自动配好适用物品和槽位。

## 迁移旧格式配置

关闭服务器，移出旧版 JAR，放入新版；**只保留一个版本**，保留插件数据文件夹。启动时自动备份原 `config.yml` 并拆分定义，保留已有附魔 ID 和设置。

已有 `enchantments.yml` 时，它是唯一附魔定义来源；旧 `config.yml` 中的附魔条目不再读取。停用旧附魔应设置 `enabled: false` 后重启，保留 ID。备份按文件说明保存，升级无需手动迁移。

完整配置、10 种内置附魔和构建方法见 [项目 README](../README.md)。
