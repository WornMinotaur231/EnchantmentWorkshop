# Enchantment Workshop / 附魔工坊 1.0.0 · 从空白制作可编程附魔

安装 EnchantmentWorkshop-1.0.0.jar（Paper 26.3 / Java 25），保留原配置目录、移出旧 JAR。输入 `/ew editor`，点击「从空白创建」。

## 创建流程

1. 输入显示名称，例如「雷雨反击」。
2. 输入唯一代码名称，例如 `storm_guard`，注册后不应改动此 ID。
3. 选择物品类别或单项物品，检查生效槽位。常用装备会自动设置槽位；选择完整注册表中的条目后需自行检查槽位。
4. 点击「效果 1 · 可编程规则」，设置触发行为、目标、条件组合和动作。
5. 调整概率、冷却、药水等级、持续时间等。可以添加多条 PROGRAM 规则，分别设置不同触发器和条件。
6. 点击保存进入只读预览，检查名称、适用范围、槽位、规则、数值和生效状态，再点击「确认保存」。预览不执行爆炸、飞行等动作。

空白附魔默认不进入附魔台、交易或战利品池；确认平衡后可以在编辑器中开启。新增 ID、适用对象、名称、等级等注册属性改变需重启；已有注册信息不变时，规则可热更新。

## 适用物品与实体类型

- 适用物品页面提供服务器实际注册的全部**物品标签**和**单项物品**，可分页浏览，不局限模板中的十类装备。
- 目标条件中可浏览服务端实体类型；药水动作可浏览服务端全部已注册药水效果。
- 这里不是 Java 类名列表。Bukkit 实体类型不包含其他插件私有的“职业”“自定义怪物种类”等抽象；对这类插件需要额外适配。
- 单项物品配置表示为 `item-tag: '@minecraft:diamond_sword'`，标签仍写 `minecraft:swords`。

## 行为、目标和动作

| 触发器 | 时机 |
|---|---|
| ATTACK | 成功造成非零实体伤害，包含投射物，投射物来源解析为射手 |
| HURT | 受到非零实体伤害，OTHER 为攻击者或投射物射手 |
| BREAK | 成功破坏方块 |
| KILL | 击杀生物 |
| INTERACT | 未被取消的主手右键事件 |
| SNEAK | 未被取消的潜行切换，下一 tick 读取新状态 |
| PERIODIC | 每秒检查一次，适合持续装备条件 |

SELF 是附魔持有者；OTHER 是攻击目标或伤害来源，仅 ATTACK/HURT 可用。熔岩、摔落等没有实体来源的伤害不会触发 HURT。事件触发时读取当前装备，并检查 active-slots；同一附魔规则在多个槽位出现时只执行一次。

| 动作 | 参数与约束 |
|---|---|
| POTION | potion、duration-ticks、amplifier、amplifier-per-level；可作用于自己或 OTHER |
| HEAL | value / per-level 是生命点，2 点 = 1 心；单次最多 20 点，遵守回血事件 |
| IGNITE | duration-ticks 控制燃烧时长，最多 30 秒，触发原生点燃事件 |
| LAUNCH | value / per-level 设置向上速度，最大 2；可能导致后续摔落伤害 |
| EXPLOSION | value / per-level 是爆炸强度，最大 4；固定不破坏方块、不起火，仍会伤害附近实体 |
| FLIGHT | 只作用于自己，成功触发后持续允许双击跳跃飞行；每次起飞可消耗耐久，装备提供摔落保护 |

所有规则都有概率和独立的玩家冷却，最小冷却 20 tick，防止每 tick 连续执行。爆炸同步产生的伤害不会递归触发规则。关闭 allow-pvp-effects 后，玩家互相触发的规则及爆炸动作均停用；爆炸也会影响旁观实体，因此采用保守的整体停用。

飞行仅对生存/冒险模式授予权限，不接管创造模式或其他来源已提供的飞行。成功触发后不按时间到期；卸下生效装备、耐久耗尽、玩家条件不再成立、换世界、退出、死亡、配置热更新或插件关闭时回收本插件的飞行，并提供短暂缓降。持久化标记在下次进入时清理，用于异常停服恢复。与其他飞行插件同时运行时仍应联测权限争用。

## 条件

每条规则选择 `ALL`（全部条件）或 `ANY`（任一条件）。选择「无条件」会清空全部条件，对应配置 `conditions: {}`；只跳过条件限制，仍需满足触发行为、概率、冷却和装备要求。所有位置和天气条件都基于附魔持有者，而非目标位置。

| 条件 | 配置值 |
|---|---|
| sneaking / sprinting / swimming / on-ground / burning | true / false |
| health-below | 生命点小于此值，例如 8 |
| food-below | 饥饿值小于此值，例如 6 |
| world | 精确世界名称，界面可直接选择 |
| biome | 群系键，例如 minecraft:plains |
| weather | CLEAR / RAIN / THUNDER，雷暴和普通下雨分别判断 |
| time | 游戏日时间范围，例如 0,12000；跨午夜可拆成两条规则 |
| height | Y 坐标闭区间，例如 -64,40 |
| box | 方形区域 x1,y1,z1,x2,y2,z2，小坐标在前；建议同时加 world |
| permission | 玩家必须拥有的权限节点 |
| target-type | OTHER 实体类型，如 minecraft:zombie；只有存在实体上下文时满足 |
| gamemode | SURVIVAL / ADVENTURE / CREATIVE / SPECTATOR（旁观者不执行规则） |

条件页面可以修改参数或清空全部条件。输入型条件使用“删除”移除单项；选择型条件可使用指令删除。当前为扁平 ALL/ANY 条件组，不支持任意脚本、嵌套逻辑图、延迟节点或循环；一条附魔可组合最多 16 条独立效果/规则。

## 示例：雷雨中受击，给攻击者缓慢

将下面条目放入 enchantments.yml 的 enchantments 下，或通过界面逐项设置：

```yaml
  storm_guard:
    name: 雷雨反击
    description: 雷暴中被实体击中时，使伤害来源缓慢。
    max-level: 3
    item-tag: minecraft:enchantable/chest_armor
    active-slots: [chest]
    acquisition: {enchanting-table: false, villager-trade: false, random-loot: false}
    effects:
      - type: PROGRAM
        trigger: HURT
        target: OTHER
        action: POTION
        condition-mode: ALL
        conditions:
          weather: THUNDER
          world: world
        potion: minecraft:slowness
        duration-ticks: 80
        amplifier: 0
        amplifier-per-level: 1
        chance: 0.5
        cooldown-ticks: 60
```

规则也可用指令编辑，例如：

```text
/ew effect storm_guard set 1 trigger HURT
/ew effect storm_guard set 1 target OTHER
/ew effect storm_guard set 1 conditions.weather THUNDER
/ew effect storm_guard set 1 conditions.weather default
```

`default` 删除该条件。无效触发器、无 OTHER 上下文的目标、非法区域与参数会在保存时拒绝。多个服主编辑时仍执行版本冲突检查和自动备份。

兼容边界：取消的原生事件不执行对应规则；不宣称兼容所有领地、战斗或飞行插件。可视化界面是游戏内表单与选择器；未进行真实图形客户端及多插件组合联测。测试源码与运行要求见 [项目 README](../README.md)。

## 持续飞行与起飞耐久

执行动作选择「装备飞行」（`FLIGHT`）。规则成功触发后，玩家可双击跳跃开始飞行；只要来源装备仍在生效槽位、有剩余耐久且条件继续满足，飞行能力就不会因时间结束。概率和冷却仍控制规则触发，不会周期性扣耐久。希望穿戴后自动获得能力时，使用 `PERIODIC` 触发器、概率 `1` 和「无条件」。

「每次起飞消耗耐久」对应 `flight-durability-cost`，范围为整数 `0～1000`，默认 `0` 表示不扣耐久。比如设为 `1`，每次从非飞行切换到实际飞行时扣 1 点，持续悬停、移动、落地以及重复触发规则都不扣除；停止飞行后再次起飞会再次扣除。被其他插件取消的起飞事件不扣耐久。

消耗来源是授予本次飞行能力的规则对应的装备槽位。同一时刻只有一个来源，不向其他装备重复扣除。耐久消耗沿用原版耐久附魔、不可破坏属性和装备损伤事件；其他插件可以取消损伤事件。若本次起飞耗尽耐久，装备按原版机制损坏，插件结束飞行并给予 5 秒缓降。

飞行要求来源物品有耐久上限且剩余耐久大于零，包括消耗量设为 `0` 的情况。装备取下或条件失效时，最多下一次周期检查（20 个服务端刻）收回飞行；起飞时也会检查来源是否仍有效。

旧配置中的 `duration-ticks` 不再限制 `FLIGHT` 的飞行时长。`flight-durability-interval-ticks` 保留旧值校验以兼容配置，但不再参与运行，编辑器也不再显示消耗间隔。其他动作的持续时间规则不变。

## 装备摔落保护

带有 `FLIGHT` 规则的附魔装备位于配置的生效槽位、附魔启用且耐久大于零时，玩家免疫 `FALL` 类型的摔落伤害。不要求玩家先触发飞行、正在飞行或满足飞行规则的天气等条件。

该保护遵守插件的禁用世界设置。装备仅放在背包、放错槽位、卸下、耐久耗尽或附魔停用时不提供保护；也不抵挡熔岩、攻击和鞘翅撞墙等其他伤害。

## 示例：穿戴后持续飞行

以下规则放在适用胸甲、`active-slots: [chest]` 的附魔 `effects` 下：

```yaml
- type: PROGRAM
  trigger: PERIODIC
  target: SELF
  action: FLIGHT
  conditions: {}
  chance: 1
  cooldown-ticks: 20
  flight-durability-cost: 1   # 每次实际起飞扣 1 点耐久
```

修改现有飞行规则（效果序号从 1 开始）：

```text
/ew effect 附魔ID set 1 flight-durability-cost 1
/ew effect 附魔ID set 1 conditions none
```

最后一条也可使用 `conditions 无条件`，会清空全部条件。飞行耐久值非零时，动作必须为 `FLIGHT`。界面切换到其他动作会清除飞行专用参数；指令切换时需先将消耗量设为 `0`。仅修改规则且注册信息不变时，保存即可应用，不必重启。
